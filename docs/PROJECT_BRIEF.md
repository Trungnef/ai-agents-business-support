Chọn ý tưởng phù hợp cho track Agents for Business Một ý tưởng “vừa và đủ” có thể thực hiện trong vài tuần là Multi‑Agent Customer Support Assistant: Vấn đề – Nhiều doanh nghiệp vừa và nhỏ chưa có hệ thống hỗ trợ khách hàng tự động. Nhân viên phải đọc email/tin nhắn, phân loại vấn đề (đòi hoàn tiền, sai hóa đơn, hỏi tình trạng đơn hàng…), tra cứu dữ liệu rồi trả lời, tốn thời gian và dễ sai sót. Giải pháp – Xây dựng một hệ thống gồm ba agent: Agent phân loại ý định: nhận câu hỏi của khách, phân tích intent (hoàn tiền, hủy đơn, vấn đề thanh toán, hỗ trợ đăng nhập…) và mức độ ưu tiên (cao/trung bình/thấp). Agent truy xuất dữ liệu: dựa trên intent, truy xuất thông tin đơn hàng, khoản thanh toán… từ nguồn dữ liệu giả lập (CSV hoặc API mẫu). Agent phản hồi: tạo câu trả lời thân thiện, bao gồm hướng dẫn hoặc thông tin cụ thể, và đảm bảo tuân thủ chính sách (an toàn thông tin). Đây là ví dụ tiêu biểu cho track Business vì nó tự động hóa quy trình doanh nghiệp với các tác vụ tách biệt nhưng liên kết. Ngoài ra bạn có thể tham khảo các ý tưởng khác như agent xử lý báo cáo chi phí, agent phân tích pipeline bán hàng, hoặc agent tạo báo cáo tài chính. 3. Thiết kế kiến trúc và xác định khái niệm cần áp dụng Mô tả tổng quan – Vẽ sơ đồ luồng: người dùng gửi yêu cầu → MCP server phân phối tới agent phân loại → agent truy xuất dữ liệu → agent phản hồi → trả kết quả. Việc này đáp ứng tiêu chí Core Concept & Value trong phần đánh giá kaggle.com . Chọn công nghệ: dùng Agent Development Kit (ADK) của khóa học để định nghĩa agent, dùng MCP server làm “dispatcher”. Cần trình bày cách sử dụng ít nhất 3 khái niệm (multi‑agent, MCP, skill CLI hoặc security) kaggle.com . Bảo mật – Che dấu thông tin nhạy cảm (như số thẻ) khi phản hồi; sử dụng kỹ thuật kiểm soát truy cập file dataset; mô tả biện pháp trong writeup. Triển khai & giao diện – Bạn có thể xây dựng giao diện CLI đơn giản hoặc endpoint REST (nếu đủ thời gian) để người dùng gửi yêu cầu. Tuy không bắt buộc deploy public, nhưng README phải hướng dẫn chạy demo local. 4. Thiết lập môi trường phát triển Cài đặt ADK – Clone repo ADK từ khóa học hoặc pip install gói tương ứng; đảm bảo Python ≥3.10 và có quyền tạo environment. Chuẩn bị data – Tạo một file CSV giả lập gồm danh sách đơn hàng, trạng thái, mã khách hàng… để agent truy xuất. Tạo cấu trúc dự án – Thư mục src/agents/ chứa code agent; server/ cấu hình MCP; data/ chứa file dữ liệu; tests/ chứa script kiểm thử; README.md mô tả. 5. Phát triển các agent và skill Agent phân loại ý định Sử dụng mô hình ngôn ngữ (Có thể dùng API miễn phí hoặc mô hình opensource nhỏ) để trích xuất ý định và mức độ ưu tiên. Prompt tham khảo: “Bạn là trợ lý phân loại ý định. Cho câu hỏi của khách: ‘{{customer_message}}’, hãy xác định loại yêu cầu (refund, order_status, account_issue, other) và urgency (low, medium, high). Trả kết quả dưới dạng JSON.” Agent truy xuất dữ liệu Đọc file CSV theo ID đơn hàng hoặc email. Prompt/tham số: get_order_details(order_id) – trả về trạng thái, ngày giao dự kiến. get_account_issue(email) – kiểm tra lịch sử đăng nhập. Agent phản hồi Tạo câu trả lời dạng tự nhiên dựa trên intent và dữ liệu. Prompt tham khảo: “Bạn là trợ lý chăm sóc khách hàng. Với intent {{intent}}, dữ liệu liên quan {{data}}, hãy soạn email ngắn gọn, thân thiện, dùng ngôi ‘bạn’/‘quý khách’, cung cấp thông tin và hướng dẫn tiếp theo. Không lộ thông tin nhạy cảm.” Orchestrator (MCP server) Viết script điều phối: nhận message, gọi agent phân loại, truyền kết quả sang agent truy xuất dữ liệu nếu cần, cuối cùng gọi agent phản hồi. Xử lý trường hợp bất thường (intent không xác định → trả lời chung). 6. Kiểm thử, tối ưu và hoàn thiện Test unit – Viết các test case cho từng agent để đảm bảo logic hoạt động đúng với input mẫu. Test end‑to‑end – Chạy chu trình hoàn chỉnh; dùng nhiều tin nhắn với các tình huống khác nhau. Đánh giá – Đo lường độ chính xác của phân loại và sự phù hợp của phản hồi; ghi nhận điểm mạnh/yếu để mô tả trong writeup. Tối ưu – Nếu thời gian cho phép, thử thay mô hình khác hoặc cải tiến prompt để tăng chất lượng. 7. Soạn Kaggle Writeup (≤ 2 500 từ) Báo cáo là phần quan trọng trong đánh giá (10 điểm).
